# Experiment 6 — Design a Simple 1-Hop Network Using GNS3

## Objective

Design a simple **1-hop network** in GNS3, configure IPv4 addresses, verify connectivity using `ping`, and capture the exchanged packets using Wireshark.

> **What does 1-hop mean?**
> A 1-hop path means the traffic uses **one router** as the Layer-3 device between the source/destination network(s).

This README is written so that the experiment can be rebuilt from scratch later.

---

## 1. Software / Components

- GNS3
- Cisco router image/template compatible with the lab setup
- 1 Ethernet switch
- 2 VPCS hosts
- Wireshark

The lab manual's GNS3 section uses a Cisco c3725 router setup and asks for the router's interfaces to be configured with IPv4 addresses. It also demonstrates packet capture in GNS3/Wireshark.

---

## 2. Topology

Build the following topology:

```text
                   R1
                 f0/1
                   |
                   |

             PC1        PC2
```


## 4. Start the Devices

1. Open the GNS3 project.
2. Start R1, Switch1, PC1 and PC2.
3. Wait for the links to become active.
4. Open the console of R1.

---

## 5. Configure R1

Enter the following commands in the R1 console:

```text
enable
configure terminal
interface f0/1
ip address 10.0.0.1 255.255.255.0
no shutdown
exit
end
```

### What the important commands do

| Command | Purpose |
|---|---|
| `enable` | Enters privileged EXEC mode |
| `configure terminal` | Enters global configuration mode |
| `interface f0/1` | Selects the Fast Ethernet interface |
| `ip address ...` | Assigns the IPv4 address |
| `no shutdown` | Enables the interface |
| `end` | Returns to privileged EXEC mode |

## 8. Test Connectivity

From PC1, ping PC2:

```text

```

A successful test should show replies from `10.0.0.3`.

You can also test the router from PC1:

```text

```

## 9. Wireshark Packet Capture

The lab manual asks you to start a packet capture and observe the packets exchanged during the ping operation.

### Steps

1. In GNS3, right-click the required link/port.
2. Select **Start capture**.
3. Open the Wireshark capture.
4. Run the ping again from PC1:

```text
ping 10.0.0.3
```

5. Stop the capture after the required packets are visible.

### Useful Wireshark filter

For ping traffic, use:

```text
icmp
```

You should be able to observe ICMP Echo Request and Echo Reply packets.

## 12. Troubleshooting

### Problem: R1 interface is red/down

Check that you entered:

```text
interface f0/1
no shutdown
```

Also confirm that the cable is connected to the correct switch port.

### Problem: PC1 cannot ping R1

Check:

```text
PC1> show ip
```

PC1 should use `10.0.0.2/24` with gateway `10.0.0.1`.

On R1:

```text
show ip interface brief
```

The Fast Ethernet interface should be `up/up`.

### Problem: PC1 cannot ping PC2

Check that both PCs are on the same subnet:

```text
PC1 = 10.0.0.2/24
PC2 = 10.0.0.3/24
```

Also check the switch connections and repeat the ping.
